# Live ride (Stage 6, part 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ride-day live location sharing with emergency, dropped-out, regroup and split-group alerts.

**Architecture:**
- **Rules:** pure rules in `src/domain/liveRide.ts`, mirrored by security-definer SQL functions over two
  tables that nobody can read directly.
- **Backends:** one `LiveRideBackend` interface, with a demo backend (in memory, simulated riders) and a
  live one (RPCs).
- **Phone:** a tracker module wraps expo-location (a background task on native, a foreground watch on
  web), the offline alert queue and local notifications.
- **Screens:** the ride screen gets a card, and there's a new `LiveRide` stack screen.

**Tech Stack:** Expo SDK 58, expo-location, expo-task-manager, expo-notifications, AsyncStorage, Supabase
(Postgres + pg_cron), node:test.

**Spec:** `docs/superpowers/specs/2026-10-24-phone-superpowers-design.md` (section 1).

## Global Constraints

- **Window:** opens 2 h before the start and closes 2 h after the end. With no end, it closes at Melbourne
  midnight after the last day. All-day rides run midnight to midnight. Cancelled rides have none.
- **Personal cap:** a rider's sharing stops after 12 h, or at window close if that's sooner.
- **Leader:** an active `road_captain`, `tail_gunner` or `assistant_tail_gunner` position, or a board or
  NEC seat (`isBoardOf` for any chapter, or `isNational`).
- **Stale and split:** a rider is stale after 5 min. Split groups use fresh riders only, linked when under
  3 km apart.
- **Nothing kept:** one position row per rider per ride. Everything for a ride is deleted once its window
  closes.
- **Migrations:** prefix `20270201`. No word "drop" in any SQL.
- **Shared files:** in `types.ts`, `RootNavigator.tsx`, `navigation/types.ts`, `demoData.ts` and
  `rides.tsx`, only add, in one block marked `// Lane E: live ride`.
- **Dates and copy:** dates are shown DD/MM/YYYY and times in Melbourne time. No `Alert`, and destructive
  or emergency actions go through `ConfirmButton`.
- **Fonts:** stencil for titles, buttons, chips and numbers. The body font is only for sentences.

## Review Focus

1. **The phone's clock disagrees with the server:** the server's answer wins. The UI shows the
   server's refusal.
2. **An alert raised with no fix yet:** it's sent with null lat/lng. The UI says "location unknown" and
   still raises the alert. Test in Task 1 (`describeAlert` with null position) and Task 2 (SQL accepts
   null).
3. **The same alert sent twice from the offline queue:** the second emergency for the same rider while
   one is open returns the open one, not a duplicate. Test in Task 2.
4. **A rider who stops sharing and then restarts in the window:** the row is renewed and `stops_at`
   recomputed. Test in Task 2.
5. **Window edges across daylight saving** (first Sunday of October and April): test in Task 1.

**Interfaces:**
- **Tables:** `public.live_riders` and `public.ride_alerts`, as in the spec, with type
  `public.ride_alert_kind`.
- **Private functions:**
  - `private.is_ride_leader(uuid)`
  - `private.live_window(public.rides)` returns `(opens timestamptz, closes timestamptz)`
  - `private.live_ride_cleanup()`, run every 5 min by pg_cron (`cron.schedule` guarded by
    `if exists pg_namespace cron`, as in `20261024120100`)
- **Public functions** (all security definer, `search_path = ''`, executable by `authenticated` only):
  - `start_live_ride(p_ride uuid)` returns `timestamptz` (stops_at)
  - `update_live_position(p_ride, p_lat float8, p_lng float8, p_accuracy real, p_heading real, p_speed real)` returns `jsonb`
  - `live_ride_state(p_ride)` returns `jsonb`
  - `raise_ride_alert(p_ride, p_kind, p_lat, p_lng)` returns `uuid`
  - `resolve_ride_alert(p_alert uuid)`
  - `stop_live_ride(p_ride)`
- **State JSON:** `{ me: {stops_at} | null, riders: [{member_id, name, leader, lat, lng, accuracy_m, updated_at, phone}], alerts: [{id, ride_id, member_id, kind, lat, lng, created_at, resolved_at}], contacts: [{id, member_id, name, relationship, phone}] }`
  - `name` is `coalesce(road_name, full_name)`.
  - `phone` comes from `member_private`, and only for leaders. For leaders, it's also given for the raiser
    of an open emergency.
  - `contacts` is filled only for a leader, and only with the emergency contacts of riders with an open
    emergency.
  - The state shows unresolved alerts, plus alerts resolved in the last 10 min.

  - Starting gives `stops_at` ≤ the window close and ≤ now + 12 h. Restarting after a stop renews the row.
  - `live_ride_state` for a member who isn't sharing raises "Share your location first."
  - Two sharing riders each see both riders, and the leader's phone is visible to a plain rider.

  - A resolve by another non-leader is refused, and a resolve by the raiser is allowed.
  - Cleanup: once the ride's `starts_at` is moved into the past beyond the window, cleanup leaves 0 rows in
