# Ride crew Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every ride has a crew (RC, TG, ATG, Officers) that crew managers fill, members volunteer for, and anyone can step down from, with the same rules in the app and the database.

**Architecture:**
- **Rules:** pure functions in `src/domain/crew.ts`, mirrored by SECURITY DEFINER actions (`set_crew`, `leave_crew`) over a read-only `public.ride_crew` table.
- **Data:** `ride_calendar()` returns the crew with the rides.
- **Demo:** the demo applies the same rules through `demoActions`.
- **Parity:** `parity.json` cases prove the demo and the database agree.

**Tech Stack:** TypeScript, Expo SDK 58 / React Native, React Navigation, Supabase Postgres (PL/pgSQL), Jest (`npm test`), `scripts/test-db.sh` (`npm run test:db`).

**Spec:** `docs/superpowers/specs/2026-10-24-ride-crew-design.md`

## Global Constraints
- **Messages:** every refusal message is word-for-word from the spec (curly apostrophes `’`), identical in the app and the database.
- **Migrations:** a new file `supabase/migrations/20261024130000_ride_crew.sql` only. Existing migrations are never edited. The word "drop" must not appear anywhere in it.
- **Shared files:** only add, in one block (lane rules in `/mnt/project-files/build/parallel-stages.md`).
- **Dates:** stored ISO `YYYY-MM-DD`, shown `DD/MM/YYYY`. Times are in Melbourne.
- **UI:** no `Alert`; take-off uses `ConfirmButton`. The Rustnuts Stencil font is used for labels, chips, buttons and names. Colours and fonts come from `src/theme.ts`.
- **Navigation:** React Navigation only, state-based.

## Review Focus
1. **Same-ride moves.** Someone already holding a spot is assigned another single spot on the same ride: they move, and nobody ends up holding two.
2. **Manager replaces a holder** who is also a crew manager themselves: the old holder's RSVP stays unchanged.
3. **All-day and multi-day rides.** The crew window closes at the end of the first Melbourne day, across the daylight saving change (1 Oct / 5 Apr style dates).
4. **Live mode can't see first aid.** A cross-chapter manager can't see a member's first aid date: the app lets the pick through, and the database's refusal message shows inline.
5. **Cancelled ride with an existing crew:** the crew still displays (as a record), but no buttons do anything and no Crew needed tag shows.

**Interfaces:**
- **Produces:**
  - `type CrewRole = Extract<PositionRole, 'road_captain' | 'tail_gunner' | 'assistant_tail_gunner' | 'officer'>`
  - `interface CrewSpot { rideId: string; memberId: string; role: CrewRole; assignedBy: string | null; assignedAt: string }`
  - `CREW_ROLES: CrewRole[] = ['road_captain','tail_gunner','assistant_tail_gunner','officer']`. Labels come from the existing `ROLE_LABEL` and `ROLE_SHORT`.
  - `endOfFirstDay(ride: Ride): number` (epoch ms). This is the first Melbourne midnight after the ride's Melbourne start date, for any ride, timed or all-day. Reuse the 23/24/25-hour search that `answersClose` uses: make `answersClose`'s all-day branch call it.
  - `managesRide(me: Member | null, ride: Ride, data: ClubData): boolean`. Approved and one of:
    - `isNational`
    - for a `north` or `west` ride, a board seat or an active `ride_committee` position in the chapter with that slug
    - for any other category, any board seat or any active `ride_committee` position.
  - `eligibilityProblem(target: Member, role: CrewRole, ride: Ride, data: ClubData): string | null`. Checks, in order:
    1. Not approved, or status not full/nomad: `Only Full and Nomad members can crew a ride.`
    2. On hiatus: `Members on hiatus can’t crew a ride.`
    3. TG or ATG, when a `privates` row for the target exists and its `firstAidExpiry` is null or before `melbourneDate(ride.startsAt)`: `Tail Gunners need a current first aid certificate on file.` With no row, it passes.
  - `crewProblem(me: Member | null, ride: Ride | undefined, target: Member | undefined, role: CrewRole, data: ClubData, now: string): string | null`. Checks, in order:
    1. `Sign in first.`
    2. `Only approved members can do that.`
    3. `No such ride.`
    4. `That ride was cancelled.`
    5. `now >= endOfFirstDay`: `The crew can’t change after the ride day.`
    6. Target missing: `That member no longer exists.`
    7. Target ≠ me and not managing: `Only the board or ride committee can put someone else on the crew.`
    8. `eligibilityProblem`.
    9. Target ≠ me and the target's RSVP is `no`: `They said they can’t make it.`
    10. A non-officer role held by someone other than the target, and not managing: `That spot’s taken.`
  - `leaveProblem(me: Member | null, ride: Ride | undefined, targetId: string, data: ClubData, now: string): string | null`. Checks 1 to 5 as above, then:
    - Target ≠ me and not managing: `Only the board or ride committee can take someone else off the crew.`
    - No spot for the target on that ride: `They’re not on the crew.`
  - `crewFor(rideId: string, crew: CrewSpot[]): CrewSpot[]`. Ordered by `CREW_ROLES` index, then by `assignedAt`.
  - `crewNeeded(ride: Ride, crew: CrewSpot[]): boolean`. False if cancelled. Otherwise true when no `road_captain` or no `tail_gunner`.
  - `pickList(ride: Ride, role: CrewRole, me: Member, data: ClubData): Member[]`. Eligible members only (`eligibilityProblem` null). The order is:
    1. RSVP `going`.
    2. Standing holders of `role`, in the ride's chapter for north/west, otherwise in `me.chapterId`.
    3. The rest.
    Each group is sorted by `roadName ?? fullName` (case-insensitive). Members whose RSVP is `no` are left out.

### Task 2: Crew in the database

**Files:**
- Create: `supabase/migrations/20261024130000_ride_crew.sql` and `supabase/tests/ride_crew_test.sql`.
- Modify: `scripts/test-db.sh`. Add a `rustnuts_crew` database block before the final echo, copying the rides block.

**Interfaces:**
- **Produces:**
  - The `public.crew_role` enum.
  - The `public.ride_crew` table (columns as in the spec). Its `assigned_by` references members, `on delete set null`.
  - `private.manages_ride(p_ride uuid) returns boolean`. Uses `auth.uid()`, the same rule as `managesRide`, and the active positions (`ended_on is null`).
  - `public.set_crew(p_ride uuid, p_member uuid, p_role public.crew_role) returns void`.
  - `public.leave_crew(p_ride uuid, p_member uuid) returns void`.
  - `public.set_rsvp` (create or replace, same signature), with the crew removal added.
  - `public.ride_calendar()` (create or replace), adding `'crew'`. The crew rows for the shown rides are ordered by `ride_id, role, assigned_at` and rendered with `to_jsonb`.
- **Rules:** the same checks and messages, in Task 1's order.
  - The first-day end is `((date(starts_at at time zone 'Australia/Melbourne') + 1)::timestamp at time zone 'Australia/Melbourne')`.
  - First aid uses `member_private.first_aid_expiry`, null or `< date(starts_at at time zone 'Australia/Melbourne')`. The database always checks it.
  - The "They said they can't make it" check reads `rsvps`.
- **`set_crew` steps:**
  1. If the role isn't `officer`, remove the other holder of that role on the ride (only reachable as a manager).
  2. Upsert on (`ride_id`, `member_id`), setting `role`, `assigned_by = auth.uid()` and `assigned_at = now()`.
  3. Upsert the target's RSVP to `going`.
- **Grants:** revoke all on the table from public, anon and authenticated. Grant select to authenticated, with a policy using `private.is_approved_member()`. Grant execute on both actions to authenticated only.
